# 项目宪法（Constitution）

适用范围：本仓库的杀戮尖塔（Slay the Spire）1.x 版本 mod 的全部功能。

具体游戏补丁版本，以及 BaseMod / StSLib 的版本，由构建配置记录，不在本文件中重复。

本文件只收录可判定的约束。每条原则给出"违规判定"，供 `/speckit-analyze` 逐条核对。

---

## 一、依赖边界（Dependencies）

本 mod 仅依赖 BaseMod 与 StSLib。

**违规判定**：构建配置中除 BaseMod、StSLib 及 Java 标准库之外，出现任何第三方依赖。

若某功能看似需要新库，先降级实现或自行实现，不得以"更方便"为由引入依赖。

---

## 二、文本与本地化（Localization）

所有面向玩家的文本（卡牌名、卡牌描述、遗物说明、能力提示等）必须外置于 `strings/` 资源。该资源目录位于 `src/` 层内（`src/main/resources/` 之下），不放在顶层。

**违规判定**：两种语言的 key 集合不一一对应；或代码中出现玩家可见的字符串字面量。

---

## 三、原版改动的可追溯性（Vanilla changes）

允许修改原版卡牌 / 遗物 / 事件的数值与行为。

所有此类改动必须集中在约定的 patch 包（如 `patches/vanilla/`）内。该包位于 `src/` 层内（`src/main/java/` 之下的 mod 包命名空间内），不放在顶层。

**违规判定**：在其它目录中直接改写原版行为。

本原则只约束改动发生的位置，不限制改动的幅度与数量。

---

## 四、存档兼容（Save compatibility）

**违规判定**：加载旧版本存档时抛出异常；或新增的存档字段没有可缺省的默认值。

若功能本身不写存档，则自动满足本原则。

---

## 五、完成标准（Definition of done）

一个功能只有在同时满足以下三点时才算完成：

1. 构建通过；
2. 在游戏中至少实测一次；
3. 留下可复现的验证步骤（在哪个界面、做什么操作、预期看到什么结果）。

**违规判定**：任务被标记为完成，但缺少上述任一项。

仅代码写完不算完成。

---

## 六、三层归属与写入边界（Three-layer ownership）

本项目的具体资源分三层，各自独立成仓库，只在自己的目录内写入：

- `specs/` —— 由 speckit 流程写入的 spec / plan / tasks；
- `memory/` —— 由 `agent-dev-memory` 技能写入的热状态、决策日志与两套库；
- `src/` —— 全部代码、数据与资源。

顶层目录只放项目配置与三层挂载点，不放任何具体资源或产物。

**违规判定**：某一层的内容写在另一层目录内；或顶层目录出现代码、数据、资源文件、构建产物。

内容边界：memory 只登记 `specs/` 与 `src/` 的路径引用，不复制其内容；验证记录写进 spec 文档，不写进 memory。

---

## 七、版本锁定（Version locking）

三层各自是独立 Git 仓库，由顶层仓库以 submodule 挂载；顶层只以 gitlink 锁定三层的提交。

**违规判定**：任一层未以 gitlink 形式挂载（如直接提交文件、或挂载在工作区外）；gitlink 落后于该层当前提交而未在同一里程碑提交；`.gitmodules` 中使用无法解析的地址。

锁定的提交在冻结点必须是规范的：spec 冻结时、以及每次完整验证通过时，三层指针与该层实际提交一一对应。

---

## 八、构建配置归属（Build configuration）

构建与依赖配置——`pom.xml`、依赖版本与仓库声明、工具链与 Java 目标版本、`AGENTS.md`——留在顶层仓库。

**违规判定**：构建配置被放进任一层子模块；或依赖版本只记录在子模块内，导致顶层无法独立复现该版本。

---

## 九、提交顺序（Commit order）

提交顺序固定为：先提交被改动的层，再提交顶层以推进对应指针。

**违规判定**：顶层指针先于对应层的提交被提交；或某层已提交而顶层指针未在同一里程碑推进。

---

## 附：有意未收录的约束

以下类别在本项目当前阶段**刻意不写**，以免成为无法执行的空条款。若日后确实被问题驱动，再逐条加入：

- 与其他 mod 的共存规则（不覆盖他人注册项）；
- 仓库纪律（不提交游戏本体资源与反编译代码）；
- 新增内容的总开关要求；
- 各层的技能契约细则（memory 的字段表、索引协议、`coldStart` 上限等）——那些属于技能自身，写进本文件只会多出一份会漂移的副本。
